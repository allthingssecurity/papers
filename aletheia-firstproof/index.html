2026 · Google DeepMind

An AI mathematics research agent, powered by Gemini 3 Deep Think, autonomously solved 6 out of 10 research-level math problems in the inaugural FirstProof challenge — without any human mathematical guidance.

Why Should You Care?

Imagine a world where AI can do original mathematical research — not just solve homework problems, but tackle unsolved questions that even professional mathematicians find challenging.

In February 2026, Google DeepMind's Aletheia agent did exactly that. Given 10 research-level math problems (some never solved before), it autonomously solved 6 of them in just 8 days — submitting 52 minutes before the deadline.

This is like a chess computer, but for mathematical creativity. It doesn't just verify proofs — it invents them.

The Big Idea: A Mathematical Research Assistant

Think of Aletheia as a tireless mathematician with two brains working together:

  • The Generator — like a creative artist who brainstorms possible solutions
  • The Verifier — like a strict editor who checks every line of reasoning

Here's the clever part: if Aletheia isn't confident in a solution, it says "I don't know" rather than guessing. This self-filtering means you can trust what it does produce. Of the 6 problems it submitted answers for, experts confirmed all of them were correct (with one minor debate).

Key Takeaway

AI can now autonomously produce original, expert-verified mathematical research — not by memorizing solutions, but by reasoning through novel problems using a generate-then-verify strategy with built-in honesty about what it doesn't know.

Test Your Understanding

Q1: What makes Aletheia different from an AI that just solves math homework?

Aletheia tackled problems from the FirstProof challenge — research-level questions where the answer wasn't known in advance. This is fundamentally different from solving textbook problems with known answers.

Q2: What does Aletheia do when it's not confident in a solution?

Self-filtering is one of Aletheia's key design choices. Rather than producing potentially incorrect solutions, it honestly reports when it can't solve a problem. This made its actual submissions highly reliable.

Q3: How many of the 10 FirstProof problems did Aletheia solve?

Aletheia solved problems 2, 5, 7, 8, 9, and 10 (6 out of 10). For the remaining 4, it returned "No solution found" via its self-filtering mechanism.

How It Works: The Aletheia Pipeline

Aletheia uses a Generator-Verifier architecture built on top of Gemini 3 Deep Think. The pipeline processes each problem independently:

Step 1: Problem Ingestion

Each FirstProof problem is provided as a LaTeX-formatted mathematical statement. Aletheia receives the raw problem with no hints, references, or human guidance.

Step 2: Solution Generation

The Generator subagent produces candidate solutions. It operates autonomously, using chain-of-thought reasoning to explore proof strategies. Two independent agents (Aletheia A and B) run in parallel using different model checkpoints:

  • Aletheia A: February 2026 Gemini 3 Deep Think
  • Aletheia B: January 2026 Gemini base model

Step 3: Verification

A separate Verification prompt examines each candidate line-by-line. It produces one of three verdicts:

  • [CORRECT] — Solution is mathematically valid
  • [WRONG] — Solution contains fundamental errors
  • [FIXABLE] — Minor issues; a complete rewrite is produced

Step 4: Self-Filtering & Selection

Solutions that fail verification are discarded. If neither agent produces a verified solution, Aletheia returns "No solution found." The best verified solution is selected (best-of-2 strategy).

Q1: What are the three possible verdicts from Aletheia's Verifier?

The Verifier examines each solution line-by-line and produces exactly one of three verdicts: [CORRECT] (valid), [WRONG] (fundamental errors), or [FIXABLE] (minor issues, triggers a rewrite).

Q2: Why does Aletheia run two independent agents (A and B)?

Running two agents with different model checkpoints is a best-of-2 strategy. Each agent independently attempts the problem, and the best verified solution is selected. This is analogous to having two mathematicians independently work on the same problem.

Q3: What does high inference cost tell us about a problem?

Inference cost serves as an interpretable "difficulty signal." Problem 7, a previously unsolved open problem, required 10x more compute than the baseline Erdos-1051 benchmark, directly reflecting its greater mathematical difficulty.

Q4: How does Aletheia differ from formal theorem provers like Lean?

Aletheia operates in natural mathematical language (LaTeX proofs), which is how human mathematicians actually write. Formal provers like Lean require translation into a structured formal language, adding a significant overhead.

Technical Deep Dive: Generator-Verifier Architecture

The Aletheia system implements a two-stage pipeline with self-filtering. Let's formalize this.

Formal Problem Statement

Given a research-level mathematical problem \(P\) (as LaTeX), produce a proof \(\pi\) such that:

$$ \text{Aletheia}(P) = \begin{cases} \pi^* & \text{if } \exists\, \pi \in \Pi(P) : V(\pi) = \texttt{CORRECT} \\ \texttt{null} & \text{otherwise} \end{cases} $$
\(\Pi(P)\) candidate proof set \(V(\pi)\) verifier verdict \(\pi^*\) best verified proof

Best-of-N Strategy

With \(N=2\) agents running independently on different model checkpoints \(\theta_A, \theta_B\):

$$ \begin{aligned} \pi_A &\sim G(\cdot \mid P; \theta_A) \\ \pi_B &\sim G(\cdot \mid P; \theta_B) \\ \pi^* &= \arg\max_{\pi \in \{\pi_A, \pi_B\}} \mathbb{1}[V(\pi) = \texttt{CORRECT}] \end{aligned} $$
\(G\) generator distribution \(\theta_A, \theta_B\) model checkpoints

Verification Prompt Design

The verification stage is critical. It uses a structured prompt that enforces line-by-line examination:

$$ V(\pi) = \text{LLM}\Big(\underbrace{\text{``Examine each step..."}}_{\text{system prompt}} \;\|\; \underbrace{P}_{\text{problem}} \;\|\; \underbrace{\pi}_{\text{candidate}}\Big) \in \{\texttt{CORRECT}, \texttt{WRONG}, \texttt{FIXABLE}\} $$

When the verdict is [FIXABLE], the verifier produces a complete rewrite \(\pi'\) rather than patching the original — eliminating error propagation from partial fixes.

Inference Cost Analysis

The paper reveals that inference cost scales non-linearly with problem difficulty. Defining cost ratio relative to the Erdos-1051 baseline:

$$ R(P_i) = \frac{C_{\text{Aletheia}}(P_i)}{C_{\text{Erdos-1051}}} $$
\(R\) cost ratio \(C\) inference compute

Problem 7 (an open problem from Weinberger's book on surgery theory) had \(R \gg 10\), making it the most computationally expensive problem to solve.

Implementation Sketch

A simplified pseudocode implementation of the core Aletheia pipeline:

import gemini from typing import Optional class Aletheia: def __init__(self, gen_model, ver_model): self.generator = gemini.load(gen_model) self.verifier = gemini.load(ver_model) def solve(self, problem: str) -> Optional[str]: # Step 1: Generate candidate proof candidate = self.generator.generate( system="You are a research mathematician...", prompt=problem, max_tokens=32000 ) # Step 2: Verify line-by-line verdict = self.verifier.generate( system="Examine each step for correctness...", prompt=f"{problem}\n\nCandidate:\n{candidate}" ) # Step 3: Self-filter if "[CORRECT]" in verdict: return candidate elif "[FIXABLE]" in verdict: return self._extract_rewrite(verdict) return None # "No solution found" # Best-of-2 strategy a = Aletheia("gemini-3-deep-think-feb", "gemini-3-deep-think-feb") b = Aletheia("gemini-3-deep-think-jan", "gemini-3-deep-think-jan") for problem in firstproof_problems: sol_a = a.solve(problem) sol_b = b.solve(problem) best = sol_a or sol_b # Prefer verified solution

Open Questions

  • Scaling laws for mathematical reasoning: How does inference cost relate to problem difficulty in a formal, predictable way? Can we build a "difficulty predictor"?
  • Formal verification integration: Could Aletheia's natural-language proofs be automatically translated to Lean/Coq for machine-checkable verification?
  • Multi-problem reasoning: Aletheia treats each problem independently. Could cross-problem insight transfer improve performance?
  • Citation and attribution: The paper acknowledges that citation standards don't meet FirstProof requirements. How should AI-generated proofs cite prior work?
  • Optimal N for best-of-N: With N=2, Aletheia solved 6/10. What is the expected gain from N=4, N=8, or higher?

Test Your Understanding

Q1: In the formal pipeline, what happens when the verifier returns [FIXABLE]?

When the verdict is [FIXABLE], the verifier produces a complete rewrite rather than patching. This design choice eliminates error propagation that could occur from partial modifications to a flawed proof.

Q2: Why might increasing N in the best-of-N strategy have diminishing returns?

Best-of-N samples from the same generator distribution. If a problem lies outside the model's capability boundary (as with problems 1, 3, 4, 6), no number of independent samples will produce a correct solution. This is why different model checkpoints (theta_A vs theta_B) are used — they sample from slightly different distributions.
